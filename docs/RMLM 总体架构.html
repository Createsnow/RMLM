研发物料管家 RMLM 总体架构

v1.2（2026-11-25，对应 rmlm-v1 分支 8db3d96）：在 v1.1（简版蓝图 V1.1 + 双端原型 + 仓储赋码）基础上，按业务 2026-11-25 确认的细节需求和四轮代码检查更新。绿色标出的是 v1.1 之后新增或改动的部分：整单批量签收；去向增加 D08 委外加工、D09 展会 / 出差（外出只改位置）、D10 外部送样；金蝶研发领料按“研发测试 / 客供领料其他出库单”自动拉取，退料 / 报废单按单号取单；金蝶反审核进差异池；有待复核冲销不能关账；审核通过派“待开单”；处置类待办办完自动关闭；离职检查扩到待确认转交和未开完单的申请；改直属上级后改派待审的续期 / 改归还日；最上级不冻结。金蝶只读、企业微信只做入口、仓储赋码、OA 不接，均不变。

一、系统架构

外部系统：金蝶只读（物料、研发领料单已接 WebAPI：研发领料 = 其他出库单中“研发测试其他出库单”“客供领料其他出库单”，每 15 分钟增量拉取；退料 / 报废单在分摊、批次核销时按单号取回；A 转 B、调整单一期手工录入 / Excel 导入；项目档案表单待确认，暂用 Excel 导入；均待内网联调）；企业微信确定使用；仓储系统已在用，实物条码由仓储赋码：签收时实时查码核对，拆分时调接口申请新码（接口由本系统拟定、仓储实现，见《仓储接口规范》），查不到的码一律拦下。旧台账 Excel 只导入一次，作为历史基线供查询和总量核对，不生成领用行、不参与对账与考核。

二、业务主流程

泳道分两组：上面四条是人，下面四条是系统（企业微信、RMLM 中台、金蝶 ERP、仓储系统）。人工步骤里的蓝字标出在哪个系统里操作：“在 RMLM”的步骤用手机或电脑都可以（系统按屏幕自动选界面），现场扫码用手机或 PDA 扫码枪更方便；领料专员开单在金蝶。企业微信只给一个入口：工作台应用点开就是 RMLM 网页并免密登录（手机企微在内置浏览器里打开，电脑版企微同样可用），另外负责通讯录和消息推送，不保存业务数据，所以它的泳道里只有推送节点。虚线是系统之间自动取数（金蝶领料单每 15 分钟拉取；退料 / 报废单分摊时按单号取；签收时实时向仓储查码），绿色为 v1.2 改动的节点。图中只画主路径。物料在仓库入库时已由仓储系统赋码贴标（B1），系统生成领用行时只有行号，使用人签收时必须扫实物上的仓储码，系统实时向仓储核对“已出库、物料一致、出库单号是本单、没挂过别的行”，扫到的码数量合计须等于领用数量，扫了几个码就分成几条领用行（B2）。签收有两条路，进同一套校验：直接扫仓储码；或扫 / 输入 ERP 单据号，系统列出这张单上属于本人的行，逐行签收，一人领整单时也可整单批量签收（v1.2，限同一张已过账单据、整单拍一组照片、仍要扫码，任何一行不通过整笔不生效）。拆分时系统向仓储接口申请新码（拆出的每份和余量各一个），本系统打印标签贴上，原码立即失效。使用登记按去向卡附加要求：D01 必须填出货单号，D03 必须选产线工位，D02 送实验室后 30 天未回填结论进预警待办，D10 外部送样必须写收样方；D08 委外加工、D09 展会 / 出差不扣结存，只改位置（可填临时位置文本），回来后“更新位置”选回固定库位。转交的受让人不在通讯录时标“外部·待认领”，持有人和责任不变，由领料专员指派到账号后再走受让人确认。审核通过即给领料专员推送“待开单”，开够申请数量后自动关闭。开单过账后系统自动拉单建行；定时任务巡检超时、超期、冻结、差异并按三级升级推送企微；处置类待办（超期、须全额退库、结项清零、待开退料单等）事情办完自动关闭，不再误升级。金蝶已过账的单据被反审核 / 作废，进差异池并提醒领料专员；关账前该月及之前不能有待复核的冲销。

三、对外边界

  • 金蝶只读。中台不写金蝶，两边只用“单据号 + 行号 + 数量”对账。物料档案每天增量同步；研发领料（其他出库单·研发测试 / 客供领料）每 15 分钟拉取，过账后按备注里的申请号自动生成领用行，使用人直接签收；匹配不上的由领料专员手工绑定，开单数量合计不能超过申请数量。退料 / 报废单不批量拉，分摊或批次核销时输入金蝶单号按单取回。A 转 B、调整单一期手工录入；项目档案表单待确认，暂用 Excel 导入。
  • 物料码取自仓储。条码由仓储系统统一赋码，本系统不另编一套码。两个接口由本系统拟定、仓储实现：查询条码（物料、数量、状态、出库单号）、拆分申请新码（幂等，余量也换新码）。一件一码、一批一码都支持。拆分守恒、最多三层、父子追溯照旧；新码由本系统打印 50×30mm 二维码标签。
  • 旧台账一次导入。只作历史基线，用于查询和总量核对，不生成领用行、不参与对账和验收指标；第 3 月起旧文件转只读归档。
  • 确定使用企业微信，只做入口。工作台应用主页填 RMLM 网址（RMLM_PUBLIC_URL 根地址），点开就是 RMLM 网页，网页授权免密登录，手机和电脑版企微都可用；不经过企微时用浏览器打开、账号密码登录；人员和直属上级每天从通讯录同步（离职人员须名下结存清零、转给他的转交已处理、本人未开完单的申请已撤回才停用）；待办、升级和关账提醒推送应用消息，失败每 15 分钟补发、最多 3 次，以站内待办为准。OA 不接。
  • 部署。应用放内网（要访问金蝶内网地址），由 DMZ 的 HTTPS 反向代理以企业已备案域名对外（RMLM_PUBLIC_URL，需在企微后台设为可信域名），出口 IP 填进企微后台的企业可信 IP。密钥只写在服务器 .env。

四、按建议默认的口径与遗留问题

  1. D02 可靠性实验的结论回填期限默认 30 天，超期派预警待办给持有人，并按现有机制 48 小时升级直属上级。
  2. 外部受让人由领料专员指派到系统账号（新人先开号或等企微通讯录同步）；指派前持有人和超期责任都不变。
  3. 历史基线：此前方案写的是“历史台账不导入、从零开始”，现按简版蓝图 5.2 改为“导入为只读基线”，仅查询和总量核对，不影响任何考核数字。
  4. 双轨抽查样本：每周从当周签收的行里随机抽 20 行（不足 20 行全抽），由领料专员对照旧表登记结果。
  5. D01 出货单号先手填（不校验金蝶出货单），金蝶销售出库单表单确认后再接校验。
  6. 仓储码签收校验：签收必须扫码。每个码实时向仓储核对：已出库、物料与领用行一致、有出库单号时须是本行的金蝶单、没挂过别的行；扫到的码数量合计须等于领用数量，扫了几个码就分成几条领用行，对账按单据行合计。
  7. 仓储接口出错时签收 / 拆分整笔不生效，提示稍后重试；未配置仓储接口时本系统发 RM 临时码，仅供开发、演示。
  8. 遗留（业务确认先遗留）：冲销拆分不连带冲销拆分时的损耗、不作废仓储已发的新码；关账后仍可审核引用已关账月份单据的调整单；仓储拆分幂等键联调时与仓储约定。
  9. 待确认：客供料在台账 / 项目视图是否显示金额；客供料退料 / 报废在金蝶用哪类单据。
  10. 待联调：金蝶内网与 API 权限、企业微信真实环境、仓储接口实现；已部署环境 .env 的 K3_LL_BILL_TYPES 加客供领料并全量同步一次。
