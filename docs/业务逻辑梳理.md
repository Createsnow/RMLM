# 研发物料管家 RMLM · 业务逻辑梳理

依据：《研发物料全生命周期管理 · 业务蓝图（简版）V1.1》、《双端可操作原型 v1.0》、[系统方案 v1.1](系统方案.md)、[仓储接口规范](仓储接口规范.md)，以及 `rmlm-v1` 分支代码（a5d93c7 起）。

本文把文档里的规则和代码里的实现逐条对上，最后列出本次代码检查发现的问题、修改和影响范围。

## 一、总原则

| 原则 | 含义 | 代码落点 |
|---|---|---|
| 一条链 | 领了必须登、用了必须记、变了必须转、废了必须销、月底必须平 | 申请 → 审核 → 开单 → 签收 → 动作 → 退库/报废 → 对账关账 |
| 两本账 | 金蝶记结果（单据、数量、金额），中台记过程（给了哪个项目、在谁手上、还剩多少、去了哪） | 金蝶只读镜像 `erp_doc / erp_line`；中台 `ledger_line / event` |
| 三字段对齐 | 单据号 + 行号 + 数量 | `services/recon.py` |
| 一码一物 | 实物码由仓储赋码，一个码只挂一条领用行 | `material_code`、`services/wms.py` |
| 事件只增不改 | 结存、行状态、码状态都由事件推导，不落库；改错用冲销 | `services/ledger.py` |
| 系统不让 | 能不能提交、能不能结案由系统判定 | 各动作的校验（`services/lineops.py` 等） |

**角色**（`perms.py`）：使用人、领料专员、仓库、财务、系统管理员（IT）、部门负责人、研发副总、项目视图。"直属上级"不是角色，由上下级关系得出。

**数据范围**：使用人看本人 + 同组（只读）+ 下属（逐级）；负责人、副总、领料专员、财务、管理员、仓库、项目视图看全部。

**代登**：签收不允许代登；其他动作可由同组成员、持有人的直属上级或领料专员代登，留痕（`event.is_proxy`）并通知持有人。代登率 < 10% 是验收门槛。

## 二、主流程（八个环节）

| # | 环节 | 谁 | 系统卡点 | 代码 |
|---|---|---|---|---|
| ① | 提需求 | 申请人（= 使用人） | 项目只能从档案选、已结项不能选；原因 R01–R06 + 明细备注必填；物料只能扫码或选主数据、金蝶禁用的不能选；预计归还日不早于今天；被冻结的人不能申请；替别人申请算代登 | `requisition.create` |
| ② | 审核 | 直属上级（无上级 → 研发副总） | 只能同意 / 驳回，驳回必写原因；不能审自己；代理人限同级或上级；4 小时提醒、24 小时升级上一级 | `requisition.decide`、`jobs.quarter_hour` |
| ③ | ERP 出库 | 领料专员在金蝶开单过账 | 未审核的申请不能绑定单据；单据备注写申请号，系统按"申请号 + 物料"唯一对上就自动生成领用行，对不上的手工绑定；超 24 小时未绑定派"ERP 有单无明细"待办 | `erp.auto_bind / bind`、`doc_sync` |
| ④⑤ | 交接签收 | 使用人本人 | 单据未过账不能签收（紧急领用除外）；必须拍照；接了仓储必须扫仓储条码：码存在且已出库、物料一致、出库单号一致、未被占用、合计 = 行数量；扫几个码分成几条领用行 | `lineops.sign / check_sign_codes` |
| ⑥ | 使用 / 拆分 / 暂存 / 转交 | 持有人（可代登） | 见第三节各场景 | `lineops.*` |
| ⑦ | 退库 / 报废 | 持有人登记，领料专员开单核销 | 退库按行 + 实退数量，多对多分摊；整件报废两段式；残料直接清零 | `lineops.return_ / scrap`、`disposal.*` |
| ⑧ | 对账关账 | 系统比对，领料专员认领，财务关账 | 差额 ≠ 0 不能关闭差异；有差额的月份不能关账 | `recon.*` |

**紧急领用（先领后审）**：申请勾"紧急"并写口头同意情况 → 领料专员先交接（生成"紧急·待补"行）→ 使用人签收 → 24 小时内补审核和 ERP 单；超时进挂账、通知上级；补审被驳回须全额退库；紧急行 7 天或跨月仍没挂 ERP 单进差异池（`LINE_NO_ERP`）。

## 三、七个场景

### 场景一：领料登记

- 扫码为主、选单号为备，两条路进同一套校验（`services/scan.py`）。扫码入口依次识别：物料码 → ERP 单据号 → 库位码 → 申请号 → 仓储条码（实时查仓储）。
- 选单号只列出该单各行，**逐行签收**，没有整单签收接口。
- 已拆分替换（B4）的旧码扫描时拒绝，提示扫新码。

### 场景二：使用、拆分与扣料

| 动作 | 规则 | 对结存 |
|---|---|---|
| 耗用 | 去向只能选 D01 / D02 / D03；数量 ≤ 结存；必须拍照。D01 必填出货单号；D03 必选产线工位；D02 30 天内回填实验结论（追加结论事件，不改原事件） | 扣减 |
| 损耗 | 所有物料适用、不设上限；必选原因 L1–L5，L5 必写说明；必须拍照。损耗率只观察不拦截 | 扣减 |
| 拆分 | 拆出合计 + 余量 + 损耗 = 当前结存；原码立即失效，**余量也换新码**；新码继承原行、原项目；领用行最多两级、物料码最多三层；原码是仓储条码时新码向仓储申请（幂等），仓储出错整笔不生效 | 父行扣"拆出"，子行各自独立结存 |

拆错不删行：由领料专员发起冲销、IT 复核（两人不同），子行未发生业务才能冲销拆分，冲销后子行作废。

### 场景三：暂存与转交

- 暂存：必须选库位并拍照；只改位置，不动结存；已暂存的再换位置用"更新位置"；超期行不能暂存；暂存超 30 天进周报清单。
- 转交：受让人从通讯录选、写原因；受让人确认前不生效，原持有人仍担责；确认后持有人变更，超期责任随之转移。受让人不在通讯录 → "外部·待认领"，由领料专员指派系统账号后再走确认；发起人或持有人可撤回待确认的转交。

### 场景四：退库

- 使用人按行登记实退数量（≤ 结存），登记即扣结存，带"待开单"标记，状态 S6"待单据处置"。
- 领料专员在金蝶开退料单（可多行并一单）→ 在中台把退料单分摊到退库事件：按物料、先进先出，可跨多张领料单 / 多张退料单，跨单打标记。
- 摊不完的进差异池；7 天或跨月仍没挂单的退库事件进差异池（`EVT_NO_ERP`）。
- 实物回仓由仓储系统自己扫码入库，中台不推送；仓库可在中台确认实物（`warehouse_receive`）。

### 场景五：报废

| 路径 | 适用 | 流程 |
|---|---|---|
| 残料 | 物料用完后的剩余（如光缆最后 0.3 米） | 按损耗 L2 清零，不隔离、不开 ERP 报废单，直接结案 |
| 整件 | 还有实物价值但判废 | 第一段：选原因 F01–F05、选报废箱、拍照，登记即扣结存，状态 S6；第二段：每周按箱生成批次清单，领料专员开 ERP 报废单挂批次核销 |

硬约束：未挂 ERP 报废单的行不能结案。

### 场景六：超期与异常

| 情形 | 判定 | 系统动作 |
|---|---|---|
| 超期未结案 | 结存 > 0 且今天 > 预计归还日 | 每天派待办；标准类超期 14 天以上且 14 天无动作 → 冻结新领用，直属上级解冻（解冻后 14 天内不重复冻结）；长周期不触发冻结 |
| 结存异常 | 结存 < 0 或 > 行数量 | 每 15 分钟巡检锁行，派 IT 48 小时修正；冲销修正后解锁 |
| ERP 有单无明细 | 已过账领料单行 24 小时无领用行 | 派领料专员补登；补登后自动重对 |

长周期：申请人勾选、上级确认；最长 12 个月；每季度初发"在用确认"，7 天内没确认按标准类处理；续期每次 ≤ 12 个月、需上级审核。项目结项后名下有结存的行派"结项清零"待办。

### 场景七：月末对账与关账

差异类型（`recon.KIND_NAMES`）：

| 类型 | 比什么 |
|---|---|
| `LL_UNBOUND` | ERP 领料单行没有任何领用行 |
| `LL_MISMATCH` | 领料单行数量 ≠ 绑定的一级领用行数量合计（一行出多个码时合计比） |
| `TL_MISMATCH` / `BF_MISMATCH` | 退料 / 报废单行数量 ≠ 分摊数量 |
| `EVT_NO_ERP` | 中台已退库 / 整件报废，7 天或跨月仍没挂 ERP 单 |
| `LINE_NO_ERP` | 紧急交接 7 天或跨月仍没补 ERP 单 |

调整单（TZ）经财务审核后计入被调整原单行的 ERP 数量。

消差方式：中台侧错误 → 冲销（领料专员发起、IT 复核）；ERP 侧错误 → 调整单（财务审核）；漏登 → 补绑定；分摊不平 → 重新分摊。关闭差异必须选原因码（C01–C06，没有"其他"），且差额必须为 0。财务关账：只能关已结束的月份，该月及之前所有差异差额为 0 才能关；关账后该月不能再录单、不能冲销该月事件。每月 1 日提醒财务 3 日前关上月。

## 四、状态与结存

**结存** = 领用 − 耗用 − 损耗 − 拆出 − 退库 − 整件报废（被有效冲销的事件不算；暂存、转交、结论回填不动结存）。

**行状态**（显示优先级 S7/S6 > S5 > S3 > S4 > S2 > S1）：

| 码 | 名称 | 判定 |
|---|---|---|
| S0 | 待签收 | 未签收（系统新增，蓝图无） |
| S1 | 在制未使用 | 已签收、未发生任何扣减 |
| S2 | 使用中 | 已有扣减、结存 > 0 |
| S3 | WIP 暂存 | 最近一次动作是暂存 / 更新位置 |
| S4 | 已转交 | 有过确认的转交 |
| S5 | 超期未结案 | 结存 > 0 且超预计归还日 |
| S6 | 待单据处置 | 结存 = 0，但有退库 / 整件报废未挂 ERP 单，或紧急行未补齐（蓝图只写报废，系统扩到退库） |
| S7 | 已结案 | 结存 = 0 且单据齐全 |

同时显示的标记：紧急·待补、长周期、冻结、代登、自领自开、待开单、锁定、外部·待认领。

**码状态**：B1 已赋码（仓储在库，以仓储为准）→ B2 已领用（签收绑定）→ B3 部分使用 → B4 已拆分替换 / B5 已用完 / B6 已退库 / B7 已报废。行状态说"这笔领用走到哪一步"，码状态说"这件实物现在是什么身份"。

## 十、本次代码检查：问题、修改与影响范围

全部问题先写测试复现、再修改，回归测试在 `backend/tests/test_review_fixes.py`（7 个），全量 64 个测试通过。

### 1. 紧急领用补挂 ERP 单后，差异永远平不掉，月份关不了账（严重）

- **现象**：紧急交接 7 天未补单 → 生成 `LINE_NO_ERP` 差异（差额 −10）。之后正常补审核、补挂领料单，这条差异仍是 −10、状态 OPEN；财务关账报"还有 1 条差额不为 0 的差异"，且无法通过任何操作消除。
- **原因**：对账每次只重算"当前还能算出来"的差异。行补挂单据后不再算 `LINE_NO_ERP`（改由该单据行按 `LL_MISMATCH` 对账），旧差异从此没人更新。
- **修改**：`recon.run` 末尾，对 `LINE:`、`EVT:` 开头、已经算不出来的未平差异自动平账，关闭对应认领待办，备注"系统自动平账（已补挂 ERP 单 / 事件已冲销）"。`ERP:` 开头的（金蝶反审核才会消失）保持原样，由人工核对。
- **影响范围**：只影响对账结果，调用方为每日对账、手工"运行对账"、分摊后、关闭差异、关账。已在库里卡住的这类差异，下一次对账会自动平掉。无表结构变化。

### 2. 退库误登被冲销后，差异同样卡死（严重）

- **现象**：退库 4 米 7 天未挂单进 `EVT_NO_ERP`；领料专员发现是误登、冲销并经 IT 复核生效，差异仍是 −4，关不了账。
- **原因**：同第 1 条——冲销后的事件不再参与对账。
- **修改**：同第 1 条。
- **影响范围**：同第 1 条。

### 3. 冲销已挂退料单的退库，对账漏报差异（严重）

- **现象**：退库 4 米、已挂退料单 4 米；随后冲销这次退库。中台结存回到 10（视为没退），而金蝶退料单仍是 4 米，对账却显示"已平"。
- **原因**：对账统计退料 / 报废单行的分摊数量时，没有排除已被冲销事件的分摊。
- **修改**：
  - `recon._compute`：退料 / 报废单行的分摊合计排除被冲销的事件 → 差额 4 进差异池，按规则开调整单或重新登记；
  - `disposal._allocated`（单据行已摊数量）同样排除 → 单据行空出的 4 米可以重新分摊给正确登记的退库事件；
  - `disposal.allocate` 不允许选已被冲销的事件。
- **影响范围**：退料 / 报废分摊与对账。只有"先分摊、后冲销"的数据结果会变化（从"已平"变为差异），这是应有的结果。冲销本身的规则不变。

### 4. 未过账的退料单 / 报废单能拿来核销，行提前结案（中）

- **现象**：在金蝶还没过账的退料单分摊后，行立即变成 S7 已结案。
- **原因**：分摊没有校验单据过账状态；而对账只看已过账单据，于是这部分既不进差异池，行又结了案。
- **修改**：`disposal.allocate` 要求单据已过账，否则提示"在金蝶尚未过账，过账后才能分摊核销"。报废批次挂单走同一函数，一并生效。
- **影响范围**：退库分摊、报废批次核销。前端单据下拉仍列出全部单据，选到未过账的会收到提示。

### 5. 报废单数量不够摊完批次时，剩余明细永远挂不了单（中）

- **现象**：批次 5 米只开了 3 米的报废单，挂单后批次即标"已核销"；剩下 2 米既不会进新批次，也不能再挂第二张报废单，行一直停在 S6。
- **修改**：`disposal.bind_batch` 摊完才置"已核销"，没摊完保持未核销并返回剩余数量 `batch_rest`，可再挂下一张报废单。前端批次列表显示"部分核销 单号"，并提示剩余数量。
- **影响范围**：报废批次核销接口与页面（`Scrap.vue`）。已经被错误标成"已核销"的历史批次不会自动改回，需要时由管理员处理。

### 6. 同一行两笔动作同时提交，结存可能被扣成负数（中）

- **现象**：两台手机同时对结存 10 的行各扣 8，两笔都成功，结存 −6（之后被巡检锁行）。
- **原因**：校验"数量 ≤ 结存"和写入事件之间没有加锁；MySQL 默认的可重复读下，即使加了行锁，普通查询也读到事务开始时的旧数据。
- **修改**：
  - 各动作的公共校验 `lineops._guard` 先对领用行 `SELECT … FOR UPDATE`，同一行的动作排队执行；冲销复核同样先锁行；
  - 动作里计算结存改用锁定读取（`ledger.load(lock=True)`，`FOR SHARE`），读到最新已提交的事件。
- **影响范围**：所有领用行动作（签收、耗用、拆分、暂存、更新位置、转交、退库、报废、季度确认、续期、改归还日）和冲销复核。只是同一行的并发请求会串行，对不同行没有影响；看板、报表等只读计算不变。

### 7. 锁行后没有解锁途径（中）

- **现象**：结存异常被锁行后，即使 IT 通过冲销把结存修回正常，行仍然锁着，所有动作都被拒绝。代码里没有任何地方解除锁定。
- **修改**：冲销复核通过后，若结存恢复正常且该行处于锁定，自动解锁、关闭"结存异常已锁行"待办，并通知持有人（原因即冲销原因，已留在冲销事件里）。蓝图 3.6 的关闭标准"结存恢复非负且原因入档"。
- **影响范围**：只影响被锁的行在冲销复核通过时的状态。
