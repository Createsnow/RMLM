# 研发物料管家（RMLM）系统方案 v1

本文档记录 v1 实现所依据的业务决策、系统设计，以及开发中自行确定、需要业务确认的边界口径。

## 一、已确认的决策

### 1. 业务规则（业务蓝图 V1.2 + Q1–Q18）

| # | 规则 | 系统实现 |
|---|---|---|
| 1 | 八个环节：提需求 → 直属上级审核 → ERP 出库 → 签收 → 使用 → 暂存/转交 → 退库/报废 → 对账 | 申请状态 + 领用行状态 S0–S7 |
| 2 | 申请人 = 使用人；替别人申请按代登留痕 | `requisition.created_by ≠ user_id` 即代申请，并通知使用人 |
| 3 | 直属上级审核，只能同意或驳回；驳回必须写原因 | 审核接口不接受数量 |
| 4 | 顶层负责人的申请由研发副总审核 | 把负责人的"直属上级"设为副总即可；没有上级时自动交给研发副总角色 |
| 5 | 4 小时提醒，24 小时升级给审核人的上级 | 每 15 分钟检查一次 |
| 6 | 代理审核人限同级或上级；任何人不能审自己的申请 | 设置代理时校验 |
| 7 | 紧急领用先领后审：24 小时内补审核和 ERP 单，超时进挂账；补审被驳回要全额退库 | 领用行标记"紧急·待补" |
| 8 | 领料原因 R01–R06，申请时必须写明细备注 | 提交时校验 |
| 9 | 长周期：申请人勾选、上级确认；不触发 2 周冻结；每季度确认在用；最长 12 个月；续期每次 ≤ 12 个月，需上级审核，次数不限 | 季初生成确认待办；7 天内没确认就按标准类处理 |
| 10 | 损耗适用所有物料，不设上限，必须选原因并拍照 | 耗用事件上的损耗标记 + 损耗原因字典 L1–L5 |
| 11 | 拆分守恒：拆出 + 余量 + 损耗 = 原数量；原码立即失效；领用行最多两级，物料码最多三层 | 余量也换新码 |
| 12 | 残料直接报废：按损耗（L2）清零，不隔离、不开 ERP 报废单；还能用的料必须退库 | 报废分"残料 / 整件"两条路 |
| 13 | 整件报废两段式：先入箱，每周按箱生成批次清单，统一开 ERP 报废单核销 | 报废批次 |
| 14 | 退库多对多分摊，先进先出，跨单打标记 | 分摊表 `doc_alloc` |
| 15 | 账平才能关账；中台侧的错误用冲销（领料专员发起、IT 复核，两人不同），ERP 侧的错误用调整单（财务审核） | 差额 ≠ 0 的差异不能关闭；有差额的月份不能关账 |
| 16 | 二级升级和解冻都由直属上级处理 | — |
| 17 | 转交需受让人确认后生效，超期责任随新持有人转移 | — |
| 18 | 签收不允许代登；其他动作可由同组成员、直属上级或领料专员代登，留痕并通知持有人 | 代登率进看板 |
| 19 | 离职或调岗前，名下结存必须清零 | 停用账号、企微通讯录同步到离职时校验；"离职检查"可随时查名下未清零的行 |
| 20 | 使用人可看本人和本组（只读）；直属上级可看下属（逐级）；项目视图角色按项目只读 | 数据范围控制 |
| 21 | 领料专员自领自开时打标记，月度抽查 | 月度清单 |
| 22 | 损耗率只观察、不拦截 | 损耗报表 |
| 23 | 一期验收门槛：项目关联率 100%、码绑定率 ≥ 95%、代登率 < 10%；其余为观察指标 | 看板 |

### 2. 系统建设

| 项 | 决定 |
|---|---|
| 金蝶 | **只读，不写金蝶**。物料档案走金蝶云星空 WebAPI，每天增量同步（见第三节）；项目档案和单据（领料 LL、A 转 B AB、退料 TL、报废 BF、调整 TZ）暂用手工录入或 Excel 导入，表单确认后实现 `ErpReader` 对应方法即可切换 |
| 企业微信 | **保留业务蓝图原做法**（2026-11 拍板）：身份登录（手机端网页授权免密）、H5 入口（企微工作台）、通讯录（人员、职务、直属上级、离职）、消息推送（站内待办同步推企微）。未配置企微时自动退回账号密码登录 + 站内待办；电脑端始终可用账号密码 |
| 仓储系统 | **不对接**（2026-11 拍板）。物料码由本系统发放（RM 开头），用标签打印机打印；码状态 B1"仓储赋码"不使用 |
| 扫码 | PDA 扫码枪（按键盘输入识别）和手机浏览器 / 企微内置浏览器摄像头 |
| 技术栈 | Python（FastAPI）+ MySQL 8；**不用 Redis**（定时任务在进程内运行，多实例时用 MySQL `GET_LOCK` 防止重复执行） |
| 照片 | **永久保存**；压缩到约 300KB，加时间和人名水印，不能删除 |
| 金额 | **显示**：物料单价取自 ERP 单据或物料主数据，台账和项目视图都显示金额 |
| 历史台账 | **不导入，从零开始** |
| 角色 | **创建账号时勾选**；"直属上级"不是角色，由上下级关系自动得出。人员和直属上级以企微通讯录为准，角色只在本系统维护 |
| 离职 / 调岗 | 名下结存必须清零。管理员停用账号时检查；企微通讯录同步发现离职时同样检查，有结存的不停用、派待办给直属上级。不单独对接 HR 系统 |
| 关账 | 每月 **3 日前**完成上月中台关账（每月 1 日给财务发待办） |

## 二、架构

总体架构图（含业务主流程泳道图）：<https://claude.ai/artifact/D8EGLrSFbW8PAYQVEAmY3t>

```
浏览器（电脑端 / 企微 H5 /m / PDA）
        │ HTTPS（DMZ 反向代理，企业备案域名）
FastAPI（同时托管前端静态文件）
 ├─ api/core.py   登录（账号密码 / 企微网页授权）、账号与组织、代理、主数据与同步、字典、待办、照片、审计
 ├─ api/biz.py    申请审核、ERP 单据、台账与动作、退库报废、对账关账、报表
 ├─ services/     requisition / erp / lineops / ledger / disposal / recon / jobs / reports / photos
 │                k3cloud（金蝶 WebAPI 只读客户端）/ master_sync（物料同步）/ wecom（企微登录、通讯录、推送）
 ├─ scheduler.py  APScheduler，每 15 分钟一次 tick
 └─ MySQL 8 ＋ 照片目录

外部：金蝶云星空 ──WebAPI 只读──→ 中台（物料；项目与单据暂用导入）
      企业微信   ←─推送── 中台 ──登录、通讯录──→（读）
```

**原则：**
- 事件只增不改：结存和状态都从事件推导；改错用"冲销"事件。
- 单据只读：金蝶单据进中台后只用于绑定、分摊和对账。
- 外部接口失败不影响业务：同步失败给管理员派待办，下次重试；推送失败以站内待办为准。
- 密钥只放环境变量（`.env`），不进代码和仓库。
- 表结构升级：启动时自动给已有表补新增的列和索引（只增不删、不改类型）。

## 三、外部接口

### 1. 金蝶云星空（只读）

| 项 | 内容 |
|---|---|
| 登录 | `LoginByAppSecret`（账套 ID + 用户名 + AppID + AppSecret + 语言 2052），会话 cookie `kdservice-sessionid` |
| 查询 | `ExecuteBillQuery` 分页（每页最多 2000 行）；单查用 `View` |
| 物料表单 | `BD_MATERIAL`。条件：已审核（`FDocumentStatus='C'`）+ 使用组织 `K3_USE_ORG`（默认 100）；增量时加 `FModifyDate >= 水位 − 10 分钟` |
| 字段对应 | 编码 `FNumber`、名称 `FName`、规格 `FSpecification`、单位 `FBaseUnitId.FName`、分组 `FMaterialGroup.FName`、内码 `FMaterialId`、禁用 `FForbidStatus`（B = 禁用） |
| 写入规则 | 按编码对齐，有则更新、无则新建；金蝶禁用的物料在中台置"停用"——保留历史引用，不能再申请；中台没用过的禁用物料不建 |
| 单价 | 不从物料档案取（样例中采购价、零售价都是 0），金额以 ERP 单据行单价为准 |
| 频率 | 每天定时增量；"主数据 → 物料"可手动增量或全量同步，并显示最近同步时间和结果 |
| 失败 | 给管理员派"同步失败"待办，不影响其他每日任务 |
| 待确认 | 项目档案的表单（物料档案里"项目名称"引用的是辅助资料，项目可能也在辅助资料里）；研发领料 / 退料 / 报废 / A 转 B 单的表单（推测为其他出库 `STK_MisDelivery`、其他入库 `STK_MISCELLANEOUS`）；API 账号对这些表单的查询权限 |

物料档案里还有两项值得后续利用：条形码子表 `FBarCodeEntity_CMK`（若仓库维护了包装条码，扫包装条码即可带出物料编码）、自定义字段"是否研发审批" `F_ora_Combo_yfsp`（含义待金蝶顾问确认）。

### 2. 企业微信（自建应用）

| 项 | 内容 |
|---|---|
| 登录 | 手机端在企微内打开时，登录页自动跳网页授权（`snsapi_base`），回到 `/login?code=…` 后换取登录凭证；按企微 UserID 找到账号。未绑定企微的账号提示"尚未开通"。原地址（如消息里的 `/m/req/12`）登录后自动回到 |
| 入口 | 应用主页设为 `{RMLM_PUBLIC_URL}/m` |
| 通讯录 | 每天同步（管理员也可手动）：用通讯录同步 Secret 读 `WECOM_ROOT_DEPT` 及下级部门的成员。按 UserID 对齐；中台已有同名且未绑定企微的账号（Excel 导入的）自动绑定；新人自动开号（只有使用人角色）；姓名、职务、直属上级（`direct_leader` 第一位）以企微为准，企微没维护直属上级的保留中台原值，会形成循环的跳过 |
| 离职 / 停用 | 企微状态为离职、禁用或移出同步范围：名下无结存直接停用；有结存的不停用，派"离职清零"待办给直属上级，清零后下次同步再停用 |
| 推送 | 每条站内待办（有企微账号的人）在事务提交后推送一条文本卡片，标题为待办内容，点开直达对应页面（审核 → `/m/approve`，申请 → `/m/req/{id}`，物料行 → `/m/line/{id}`，其余 → `/m/todos`）。失败每 15 分钟补发，最多 3 次，之后标记失败；站内待办不受影响 |
| 上线配置 | 企业 ID、AgentId、应用 Secret、通讯录同步 Secret；网页授权可信域名（须为企业已备案域名）；企业可信 IP（服务器出口 IP）；应用可见范围 = 研发部门 |
| 现状 | 代码和测试已完成（测试用模拟客户端），尚未连接真实企微 |

## 四、核心计算

- **结存** = 领用 − 耗用 − 损耗 − 拆出 − 退库 − 整件报废（被有效冲销的事件不算）。
- **行状态**：S0 待签收、S1 在制未使用、S2 使用中、S3 WIP 暂存、S4 已转交、S5 超期未结案、S6 待单据处置、S7 已结案。
  - 显示优先级：S7/S6 > S5 > S3 > S4 > S2 > S1。
  - 同时显示的标记：紧急·待补、长周期、冻结、代登、自领自开、待开单、锁定。
- **码状态**：B2 已领用、B3 部分使用、B4 已拆分替换、B5 已用完、B6 已退库、B7 已报废（不对接仓储，B1 不使用）。
- **对账**，以"单据号 + 行号 + 数量"为锚点：
  - 领料单行对比绑定的领用行数量；
  - 退料单行、报废单行对比分摊数量；
  - 调整单（财务审核后）计入被调整原单行的 ERP 数量；
  - 中台已退库或报废、但 7 天后或跨月仍未挂 ERP 单的，进差异池；
  - 紧急交接后 7 天或跨月仍未补 ERP 单的，进差异池。

## 五、定时任务

| 频率 | 内容 |
|---|---|
| 每 15 分钟 | 审核 4 小时提醒、24 小时升级；紧急领用 24 小时检查；ERP 有单无明细超 24 小时派补登；待办 48 小时升级直属上级、3 天进三级挂账（通知研发副总）；结存异常锁行；企微推送补发 |
| 每天 | 对账；超期待办；标准类超期且连续 2 周无动作 → 冻结；长周期到期前 30 天提醒续期；季度确认过期处理；项目结项检查；金蝶物料增量同步；企微通讯录同步 |
| 每周 | 按箱生成报废批次 |
| 每季度 | 长周期在用确认待办（7 天内完成）；季初超期快照（用于清理率） |
| 每月 | 提醒财务 3 日前完成上月关账 |

## 六、开发中自定的边界口径（请业务确认）

1. **新增 S0"待签收"状态**：开单后、本人签收前的行显示为 S0。S6 名称改为"待单据处置"，同时涵盖"已退库未挂退料单"和"已整件报废未挂报废单"（原蓝图 S6 只写了报废）。
2. **退库和整件报废登记时就扣结存**，用"待开单"标记跟踪 ERP 单据；挂上单据之前不能结案。
3. **中台已退库或报废但没挂 ERP 单**：7 天或跨月后进差异池，所以会影响关账。
4. **关账后**：该月份不能再录入 ERP 单据，也不能冲销该月的事件。
5. **长周期季度确认过期后补确认**：可以恢复长周期待遇。
6. **刚解冻的人 14 天内不重复冻结**，留出处理时间。
7. **续期的新归还日** = max（原归还日，今天）+ 续期月数。
8. **损耗、拆分、暂存都必须拍照**（蓝图写明的是耗用和报废必拍）；退库、季度确认、更新位置拍照为选填。
9. **初始密码**为 `Rmlm@123456`，首次登录强制修改；管理员重置密码后同样强制修改。
10. **冲销范围**：只能冲销耗用、损耗、退库、整件报废和拆分。冲销拆分时，子行必须还没发生任何业务，冲销后子行作废。
11. **金蝶禁用的物料**：中台只置为停用、不删除；已领用的行照常操作，只是不能再申请。
12. **企微通讯录自动开的账号**只有使用人角色，密码随机，只能用企微登录；需要电脑端登录的，由管理员重置密码。
13. **企微离职但名下有结存**：账号保留可用，以便本人或上级完成退库、转交；清零后下次同步自动停用。
