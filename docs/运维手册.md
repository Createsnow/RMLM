# 研发物料管家 RMLM · 运维手册

- 适用：`rmlm-v1` 分支，服务器直接部署（不用 Docker；Docker 部署见 [README](../README.md)）
- 读者：系统管理员（IT）
- 环境：以 Linux（Debian / Ubuntu）为准。Windows 服务器可直接运行 `python start.py`，命令自行换算

## 速查

| 要做什么 | 怎么做 |
|---|---|
| 启动 / 停止 / 重启 | `sudo systemctl start rmlm` / `stop` / `restart` |
| 看状态 | `systemctl status rmlm` |
| 健康检查 | `curl -s http://127.0.0.1:8000/health/ready`，正常返回 `{"status":"UP","db":"UP"}` |
| 看日志 | `journalctl -u rmlm -f` |
| 改配置 | 编辑 `/opt/rmlm/.env` 后重启（[第三节](#三日常操作)） |
| 手动备份 | `sudo -u rmlm /usr/local/bin/rmlm-backup.sh` |
| 升级 | [第八节](#八升级与回退) |
| 出故障 | [第十节](#十故障排查) |

## 一、系统概览

一个后端进程（FastAPI）同时提供页面和接口，前面由 nginx 提供 HTTPS；数据存 MySQL 8。定时任务在后端进程内运行，不需要 Redis。

| 项 | 位置 / 说明 |
|---|---|
| 程序 | `/opt/rmlm`（git 仓库） |
| 配置 | `/opt/rmlm/.env`（含密钥，权限 600，不进仓库） |
| 照片 | `/data/rmlm/photos`（永久保存，不能删除） |
| 数据库 | 公司的 MySQL 8，库 `rmlm`，字符集 utf8mb4。表结构在启动时自动创建、自动补列 |
| 服务 | systemd 服务 `rmlm`，只监听 `127.0.0.1:8000` |
| 对外访问 | nginx 443（HTTPS） |
| 备份 | `/backup/rmlm` |

**必须备份的三样：数据库、照片、`.env`。**

下文路径都按上表约定，实际不同时自行替换。

## 二、部署

### 准备清单

| 项 | 要求 |
|---|---|
| 服务器 | Linux x86_64，2 核 4G 起；照片每张约 300KB，按此预留磁盘 |
| 时区 | Asia/Shanghai（各种时限、每日任务都按服务器时间计算） |
| 软件 | Python 3.11 及以上；Node.js 18 及以上（只在构建前端时用） |
| 数据库 | 公司 MySQL 8 上建好库和账号（第 1 步），应用服务器能连上 |
| 域名与证书 | 企业已备案的 HTTPS 域名（手机扫码、企微登录都要求 HTTPS） |
| 网络 | 按需开通：金蝶内网地址、`qyapi.weixin.qq.com`、仓储系统 |

### 第 1 步：建数据库

请公司 DBA 在 MySQL 上执行（IP 和密码换成实际值）：

```sql
CREATE DATABASE rmlm DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'rmlm'@'应用服务器IP' IDENTIFIED BY '数据库密码';
GRANT ALL PRIVILEGES ON rmlm.* TO 'rmlm'@'应用服务器IP';
```

### 第 2 步：准备服务器

```bash
sudo timedatectl set-timezone Asia/Shanghai
```
```bash
sudo apt install -y git python3 python3-venv nginx rsync mysql-client fonts-wqy-zenhei
```
```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin rmlm
```
```bash
sudo mkdir -p /opt/rmlm /data/rmlm/photos /backup/rmlm /etc/rmlm && sudo chown rmlm:rmlm /opt/rmlm /data/rmlm/photos /backup/rmlm /etc/rmlm
```

检查 `python3 --version` 不低于 3.11。Debian 上 `mysql-client` 换成 `default-mysql-client`。

### 第 3 步：拉代码、填配置

```bash
sudo -u rmlm git clone -b rmlm-v1 <仓库地址> /opt/rmlm
```
```bash
cd /opt/rmlm && sudo -u rmlm cp .env.example .env && sudo chmod 600 .env
```

编辑 `/opt/rmlm/.env`，以下几项必须改：

| 配置项 | 填什么 |
|---|---|
| `DB_HOST` `DB_PORT` `DB_NAME` `DB_USER` `DB_PASSWORD` | 第 1 步的库和账号 |
| `RMLM_JWT_SECRET` | 随机字符串，用 `python3 -c "import secrets;print(secrets.token_urlsafe(32))"` 生成 |
| `RMLM_ADMIN_PASSWORD` | 初始管理员密码（账号默认是 `admin`） |
| `RMLM_PHOTO_DIR` | `/data/rmlm/photos`（去掉行首的 `#`） |
| `RMLM_PUBLIC_URL` | 对外地址，如 `https://rmlm.example.com` |

金蝶（`K3_*`）、企微（`WECOM_*`）、仓储（`WMS_*`）按需填写，不填会自动降级，见[第五节](#五外部接口)。

书写规则：一行一项，值后面不写注释；值里有空格、`$`、`\` 或引号时，用单引号包住，如 `DB_PASSWORD='a$b'`。

### 第 4 步：安装后端依赖

```bash
cd /opt/rmlm && sudo -u rmlm python3 -m venv backend/.venv
```
```bash
sudo -u rmlm /opt/rmlm/backend/.venv/bin/pip install -r /opt/rmlm/backend/requirements.txt
```

国内下载慢时在命令末尾加 `-i https://mirrors.aliyun.com/pypi/simple`。

### 第 5 步：构建前端

```bash
cd /opt/rmlm/frontend && sudo -u rmlm npm ci && sudo -u rmlm npm run build
```

国内下载慢时给 `npm ci` 加 `--registry=https://registry.npmmirror.com`。

完成后应有 `/opt/rmlm/frontend/dist/index.html`。服务器上不想装 Node.js 时，在其他机器上对同一版本构建，再把 `dist` 目录拷过来。

### 第 6 步：试运行

```bash
cd /opt/rmlm && sudo -u rmlm python3 start.py
```

看到「启动完成后浏览器打开 http://localhost:8000」后，另开一个终端执行：

```bash
curl -s http://127.0.0.1:8000/health/ready
```

返回 `{"status":"UP","db":"UP"}` 即成功，回到第一个终端按 Ctrl+C 停止。如有报错，按提示修改 `.env`（常见原因：连不上数据库、密钥没填、端口被占用）。

### 第 7 步：注册系统服务

新建 `/etc/systemd/system/rmlm.service`：

```ini
[Unit]
Description=RMLM
After=network-online.target
Wants=network-online.target

[Service]
User=rmlm
WorkingDirectory=/opt/rmlm/backend
EnvironmentFile=/opt/rmlm/.env
Environment=TZ=Asia/Shanghai PYTHONUNBUFFERED=1
ExecStart=/opt/rmlm/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers --timeout-graceful-shutdown 10
Restart=on-failure
RestartSec=10
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now rmlm
```

再执行一次健康检查，返回 UP 即成功。

### 第 8 步：配置 nginx

新建 `/etc/nginx/conf.d/rmlm.conf`，把域名和证书路径换成实际值：

```nginx
server {
    listen 80;
    server_name rmlm.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name rmlm.example.com;
    ssl_certificate     /etc/nginx/ssl/rmlm.crt;
    ssl_certificate_key /etc/nginx/ssl/rmlm.key;

    root /opt/rmlm/frontend/dist;
    gzip on;
    gzip_types text/plain application/javascript application/json text/css image/svg+xml;
    client_max_body_size 50m;          # 上传照片、导入 Excel

    # 前面还有内网代理（如 DMZ）时，取用户真实 IP（审计日志用）
    set_real_ip_from 10.0.0.0/8;
    set_real_ip_from 172.16.0.0/12;
    set_real_ip_from 192.168.0.0/16;
    real_ip_header X-Forwarded-For;
    real_ip_recursive on;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 600s;       # 金蝶全量同步、批量导入耗时较长
        proxy_send_timeout 600s;
    }
    location /health/ { proxy_pass http://127.0.0.1:8000; }
    location = /index.html { add_header Cache-Control "no-cache"; }
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        try_files $uri =404;
    }
    location / { try_files $uri $uri/ /index.html; }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

浏览器打开 `https://域名`，出现登录页即成功。

如果由 DMZ 代理负责 HTTPS，本机 nginx 只保留 `listen 80` 并去掉证书配置；DMZ 代理同样要设 `client_max_body_size 50m` 和 600 秒读超时。

### 第 9 步：上线初始化

1. 用 `admin` 和初始密码登录，点左侧栏左下角的当前账号 →「修改密码」。
2. 系统管理 → 用户管理：建账号、勾选角色、设直属上级（可用 Excel 批量导入；启用企微时点「同步企微通讯录」）。
3. 基础数据 → 基础资料：导入项目、物料、库位、报废箱（启用金蝶时，物料点「从金蝶同步」→「全量」）。
4. 启用金蝶时：仓库作业 → ERP 单据，点「从金蝶同步领料单」。
5. 配置每日备份（[第七节](#七备份与恢复)）。
6. 用电脑和手机企微各走一遍：提交申请 → 审核 → 签收。

## 三、日常操作

### 启停与查看

| 操作 | 命令 |
|---|---|
| 启动 | `sudo systemctl start rmlm` |
| 停止 | `sudo systemctl stop rmlm` |
| 重启 | `sudo systemctl restart rmlm` |
| 看状态 | `systemctl status rmlm` |
| 健康检查 | `curl -s http://127.0.0.1:8000/health/ready`（数据库不通时返回 503） |
| 实时日志 | `journalctl -u rmlm -f` |
| 今天的错误 | `journalctl -u rmlm --since today -p warning` |

- 日志里只有访问记录、警告和错误。定时任务的执行结果不写日志，查看方法见[第四节](#四定时任务)。
- 停止服务时，最多等 10 秒让正在处理的请求完成；没跑完的定时任务会自动回滚，下次重做，不会丢数据。

### 修改配置

1. 先备份：`sudo cp /opt/rmlm/.env /opt/rmlm/.env.bak`
2. 编辑 `/opt/rmlm/.env`
3. 重启：`sudo systemctl restart rmlm`
4. 执行健康检查

以下配置改完后还要多做一步：

| 配置项 | 还要做什么 |
|---|---|
| `RMLM_JWT_SECRET` | 无，但所有人都要重新登录 |
| `RMLM_PHOTO_DIR` | 改之前先把旧目录的照片整体搬到新目录 |
| `K3_LL_BILL_TYPES`、`K3_USE_ORG` | 重启后在 ERP 单据页做一次「全量同步」 |
| `WECOM_*`、`RMLM_PUBLIC_URL` | 同步修改企微后台的可信域名和应用主页 |
| `WMS_*` | 启用后签收必须扫仓储条码，改之前先和业务确认 |
| `RMLM_ADMIN_USER`、`RMLM_ADMIN_PASSWORD` | 只在首次启动（库里还没有账号）时生效，之后改了也没用 |

金蝶领料单自动同步的开关和间隔在网页上改，不用重启：仓库作业 → ERP 单据 →「自动同步设置」。

## 四、定时任务

定时任务全自动运行：服务启动 15 分钟后开始，之后每 15 分钟巡检一次。

| 周期 | 内容 |
|---|---|
| 每 15 分钟 | 拉金蝶领料单并生成领用行；补发企微推送；审核提醒与升级；各类超时检查；待办升级；结存异常锁行 |
| 每天（0 点后第一次巡检） | 对账；同步金蝶物料；同步企微通讯录；超期与冻结检查 |
| 每周一 | 生成报废批次 |
| 每季度第一天 | 发起长周期物料的季度在用确认 |
| 每月 1 日 | 提醒财务在 3 日前完成上月关账 |

**检查是否正常**（连接方法见[附录 A](#附录-a常用-sql)）：

```sql
SELECT name, last_key, last_run_at FROM job_run;
```

- `daily` 行的 `last_key` 应为今天的日期；
- 启用金蝶时，`k3_docs` 行的 `last_run_at` 距现在不应超过「同步间隔 + 15 分钟」。

**不运行的常见原因**：`.env` 里的 `RMLM_SCHEDULER` 不是 `1`；服务在反复重启（每次都活不过 15 分钟）。

**手动触发**（排除故障后验证用，令牌获取方法见[附录 B](#附录-b调用管理接口)）：

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/api/admin/jobs/tick
```

只用 `tick`：它会按周期判断，当天已执行过的任务不会重复执行。

## 五、外部接口

三个接口都是可选的，相关配置项填齐才启用，不填时自动降级：

| 接口 | 启用条件 | 不启用时 |
|---|---|---|
| 金蝶（只读） | `K3_SERVER_URL` `K3_ACCT_ID` `K3_USERNAME` `K3_APP_ID` `K3_APP_SECRET` 五项都填 | 物料、单据手工录入或 Excel 导入 |
| 企业微信 | `WECOM_CORP_ID` `WECOM_AGENT_ID` `WECOM_SECRET` 三项都填，并填 `RMLM_PUBLIC_URL` | 账号密码登录，待办只在站内显示 |
| 仓储 | `WMS_BASE_URL` `WMS_TOKEN` 两项都填 | 系统自己发 RM 码 |

### 金蝶

- **看同步状态**：仓库作业 → ERP 单据，页面顶部显示最近同步时间。
- **手动同步单据**：同一页点「从金蝶同步领料单」（增量）；旁边下拉里的「全量同步」会重新拉起始日期（默认近 3 个月）之后的单据。重复拉取不会重复入库。
- **手动同步物料**：基础数据 → 基础资料 → 物料 →「从金蝶同步」。

| 现象 | 处理 |
|---|---|
| 金蝶登录失败 | 核对账套 ID、用户名、AppID、AppSecret |
| 连接金蝶失败、超时 | 检查到金蝶服务器的网络；单据多时调大 `K3_QUERY_TIMEOUT` |
| 查询失败，提示权限不足 | 给金蝶应用账号补充查看权限 |
| 同步跳过某张单，提示已关账 | 金蝶修改了已关账月份的单据，由财务开调整单 |
| 同步跳过某张单，提示物料编码不存在 | 先同步物料，再同步单据 |
| 单据拉到了，但没生成领用行 | 属业务问题（如备注没写申请号），由领料专员在「出库开单」手工绑定 |

### 企业微信

企微后台需配置三处：应用主页填 `RMLM_PUBLIC_URL/`；网页授权可信域名填 `RMLM_PUBLIC_URL` 的域名；企业可信 IP 填服务器的出口 IP。

- 通讯录每天自动同步；需要立即同步时：系统管理 → 用户管理 →「同步企微通讯录」。
- 推送失败的消息每 15 分钟重试，3 次后放弃，站内待办不受影响。

| 现象 | 处理 |
|---|---|
| 提示「尚未开通研发物料管家」 | 用户管理 →「同步企微通讯录」 |
| 提示回调域名错误，或登录后跳到错误地址 | `RMLM_PUBLIC_URL` 与企微后台的可信域名不一致 |
| 提示 IP 不在白名单（如错误码 60020） | 在企微后台的企业可信 IP 里加上服务器出口 IP |
| 消息卡片点开打不开 | `RMLM_PUBLIC_URL` 没填，或外网访问不到 |
| 已离职的人没被停用 | 名下还有结存，系统已通知其直属上级；清零后，下次同步时自动停用 |

### 仓储

| 现象 | 处理 |
|---|---|
| 提示「仓储系统暂时连不上」 | 检查网络和仓储服务；响应慢时调大 `WMS_TIMEOUT` |
| 提示返回格式不正确、新码数量不符 | 仓储接口与[仓储接口规范](仓储接口规范.md)不一致，找仓储方排查 |

## 六、巡检

建议接入公司监控：每分钟探测 `https://域名/api/health`，连续 3 次失败时告警；磁盘使用率超过 80% 时告警。

### 每天

1. 健康检查正常。
2. 用管理员账号看「我的待办」，处理「定时任务出错」「同步失败」「锁行修正」「冲销复核」。
3. 启用金蝶时，ERP 单据页的最近同步时间正常。
4. 昨晚的备份成功：`tail -1 /backup/rmlm/backup.log` 显示「备份完成」。

### 每周

1. 检查定时任务（[第四节](#四定时任务)）。
2. 检查磁盘：`df -h /data /backup`。
3. 抽查审计日志（系统管理 → 审计日志），看有没有大量失败请求（状态码 401、403、500）。

### 每月

1. 1–3 日：把「冲销复核」全部处理完，否则财务无法关账。
2. 安装系统补丁，按升级流程在低峰期重启。

### 每季度

1. 做一次恢复演练（[第七节](#七备份与恢复)）。

> **注意**：「定时任务出错」「同步失败」两类待办处理完后**不会自动消失，页面上也关不掉**。如果不手工关闭，48 小时后会升级给上级，3 天后通知研发副总。处理完后，用[附录 A](#附录-a常用-sql) 的 SQL 关闭。

## 七、备份与恢复

### 配置每日备份（只需做一次）

**第 1 步**：新建 `/etc/rmlm/backup.cnf`，写入数据库连接信息：

```ini
[client]
host=MySQL地址
port=3306
user=rmlm
password=数据库密码
```

```bash
sudo chown rmlm:rmlm /etc/rmlm/backup.cnf && sudo chmod 600 /etc/rmlm/backup.cnf
```

**第 2 步**：新建备份脚本 `/usr/local/bin/rmlm-backup.sh`：

```bash
#!/usr/bin/env bash
# 数据库每天一份，保留 30 天；照片累积同步到 photos 目录，只增不删
set -euo pipefail
ROOT=/backup/rmlm
DEST="$ROOT/$(date +%F)"
mkdir -p "$DEST" "$ROOT/photos"
mysqldump --defaults-extra-file=/etc/rmlm/backup.cnf --single-transaction --no-tablespaces rmlm | gzip > "$DEST/rmlm.sql.gz"
rsync -a /data/rmlm/photos/ "$ROOT/photos/"
find "$ROOT" -maxdepth 1 -type d -name '20*' -mtime +30 -exec rm -rf {} +
echo "$(date '+%F %T') 备份完成：$DEST"
```

```bash
sudo chmod 755 /usr/local/bin/rmlm-backup.sh
```

**第 3 步**：设置每天 2:30 自动执行：

```bash
sudo -u rmlm crontab -e
```

在打开的文件里加一行：

```
30 2 * * * /usr/local/bin/rmlm-backup.sh >> /backup/rmlm/backup.log 2>&1
```

**第 4 步**：立即执行一次，确认能成功：

```bash
sudo -u rmlm /usr/local/bin/rmlm-backup.sh
```

输出「备份完成」，并且 `/backup/rmlm/当天日期/rmlm.sql.gz` 不为空。

**第 5 步**：用公司备份系统把 `/backup/rmlm` 同步到异地；`.env` 单独加密保存一份。

> 公司 MySQL 已统一备份时，可删掉脚本里的 `mysqldump` 那一行，只备份照片。

### 恢复

1. 停止服务：

   ```bash
   sudo systemctl stop rmlm
   ```

2. 恢复数据库（把日期换成要恢复的那天）：

   ```bash
   gunzip -c /backup/rmlm/2026-11-27/rmlm.sql.gz | sudo -u rmlm mysql --defaults-extra-file=/etc/rmlm/backup.cnf rmlm
   ```

3. 恢复照片：

   ```bash
   sudo -u rmlm rsync -a /backup/rmlm/photos/ /data/rmlm/photos/
   ```

4. 启动服务并做健康检查：

   ```bash
   sudo systemctl start rmlm
   ```

5. 通知业务：备份时间点之后的操作需要补登（金蝶单据会在下次同步时自动补回）。

### 恢复演练（每季度）

在测试机上按上面的「恢复」步骤，把备份导入测试库并启动。测试机的 `.env` 必须设置 `RMLM_SCHEDULER=0`，并清空 `WECOM_*`、`K3_*`、`WMS_*`，否则会给真实用户推送消息。登录后抽查几条台账和照片能否打开。

## 八、升级与回退

### 升级

选低峰时段，避开 0 点前后和每月 1–3 日（关账期），整个过程约 10 分钟。

1. 备份：

   ```bash
   sudo -u rmlm /usr/local/bin/rmlm-backup.sh
   ```

2. 记下当前版本号（回退时要用）：

   ```bash
   cd /opt/rmlm && sudo -u rmlm git rev-parse --short HEAD
   ```

3. 拉取新代码：

   ```bash
   sudo -u rmlm git pull --ff-only origin rmlm-v1
   ```

4. 检查有没有新增配置项（把「旧版本号」换成第 2 步的输出），有的话补到 `.env`：

   ```bash
   sudo -u rmlm git diff 旧版本号 HEAD -- .env.example
   ```

5. 更新后端依赖：

   ```bash
   sudo -u rmlm /opt/rmlm/backend/.venv/bin/pip install -r /opt/rmlm/backend/requirements.txt
   ```

6. 重新构建前端：

   ```bash
   cd /opt/rmlm/frontend && sudo -u rmlm npm ci && sudo -u rmlm npm run build
   ```

7. 重启服务：

   ```bash
   sudo systemctl restart rmlm
   ```

8. 验证：
   - 健康检查返回 UP；
   - `journalctl -u rmlm --since "5 min ago"` 里没有报错；
   - 浏览器刷新后能登录，能打开领用台账和 ERP 单据页。

表结构变更在启动时自动完成，不需要手工操作。

### 回退

1. 停止服务：

   ```bash
   sudo systemctl stop rmlm
   ```

2. 切回旧版本：

   ```bash
   cd /opt/rmlm && sudo -u rmlm git checkout 旧版本号
   ```

3. 重做升级的第 5、6 步（后端依赖、前端构建）。
4. 检查新版本有没有改表结构：

   ```bash
   sudo -u rmlm git diff 旧版本号 rmlm-v1 -- backend/app/models.py
   ```

   有输出时，用升级前的备份恢复数据库（[第七节](#七备份与恢复)）；没有输出时跳过这一步。
5. 启动服务并验证（同升级第 8 步）。
6. 问题修复后回到最新版本：先执行 `sudo -u rmlm git checkout rmlm-v1`，再重新走一遍升级流程。

## 九、账号与安全

### 账号

| 场景 | 操作 |
|---|---|
| 新建账号 | 用户管理 → 新建。不填密码时，初始密码为 `Rmlm@123456` |
| 批量导入 | 用户管理 → 导入 Excel，初始密码同上 |
| 重置密码 | 用户管理 → 编辑 →「重置密码」。保存后，此人已登录的设备全部下线 |
| 停用（离职、调岗） | 用户管理 → 编辑 → 关闭「启用」。名下还有结存等未清事项时不能停用，按提示先清零 |
| 解冻 | 只能由其直属上级在「我的团队」里解冻 |

**管理员忘记密码，且没有其他管理员时：**

1. 生成新密码的哈希值（按提示输入新密码）：

   ```bash
   /opt/rmlm/backend/.venv/bin/python -c "import bcrypt,getpass;print(bcrypt.hashpw(getpass.getpass('新密码：').encode(),bcrypt.gensalt(10)).decode())"
   ```

2. 在数据库里执行，把哈希值换成上一步的输出：

   ```sql
   UPDATE users SET password_hash='哈希值', token_version=token_version+1, active=1 WHERE username='admin';
   ```

### 安全要点

- `.env` 和 `/etc/rmlm/backup.cnf` 权限设为 600；密钥不外传，不提交到仓库。
- 8000 端口只监听本机；MySQL 只对应用服务器开放。
- 系统没有登录失败锁定，外网访问必须经过 DMZ 代理。
- 怀疑登录令牌泄露时：更换 `RMLM_JWT_SECRET` 并重启，所有人需重新登录。
- 业务数据只能通过页面修改；账目有错时走「冲销」流程，不要直接改数据库。

## 十、故障排查

先看两样：`systemctl status rmlm` 和 `journalctl -u rmlm -n 100`。

| 现象 | 处理 |
|---|---|
| 服务起不来，日志提示 `RMLM_JWT_SECRET` | 在 `.env` 里填 16 位以上的随机字符串 |
| 服务起不来，日志提示数据库连接错误 | 检查 MySQL 是否运行、`DB_*` 是否正确、账号授权、防火墙 |
| 服务起不来，提示端口被占用 | 用 `sudo ss -lntp` 找到占用 8000 端口的进程并关闭（常见是试运行的 `start.py` 没关） |
| 页面空白或 404 | 前端没构建，重做部署第 5 步 |
| 升级后页面空白 | 浏览器强制刷新 |
| 接口报 502 | 服务没在运行 |
| 接口报 504（如金蝶全量同步） | nginx 和 DMZ 代理的 `proxy_read_timeout` 设为 600s |
| 上传照片、导入 Excel 报 413 | nginx 和 DMZ 代理的 `client_max_body_size` 设为 50m |
| 照片水印里的人名是方块 | 安装 `fonts-wqy-zenhei` 后重启 |
| 历史照片打不开 | 核对 `RMLM_PHOTO_DIR`；必要时从备份恢复照片 |
| 手机扫码打不开摄像头 | 必须用 HTTPS 访问 |
| 提醒、超期的时间差 8 小时 | 把服务器时区改为 Asia/Shanghai 后重启 |
| 提醒、同步都不动了 | 见[第四节](#四定时任务)「不运行的常见原因」 |
| 领导收到「【二级】」「【三级挂账】」开头的同步失败提醒 | 管理员没关闭已处理的告警待办，见[附录 A](#附录-a常用-sql) |
| 关账时提示有待复核的冲销 | IT 到 对账与关账 →「冲销」页签复核 |
| 关账时提示差额不为 0 | 由业务处理差异；系统不支持反关账，不要改数据库 |
| 页面提示「系统内部错误」 | 按发生时间在日志里找 `unhandled error`，连同操作步骤一起交给开发 |
| 金蝶、企微、仓储相关报错 | 见[第五节](#五外部接口) |

## 附录 A：常用 SQL

连接数据库：

```bash
sudo -u rmlm mysql --defaults-extra-file=/etc/rmlm/backup.cnf rmlm
```

查询可以随时执行；修改数据前先备份。

**定时任务执行记录**

```sql
SELECT name, last_key, last_run_at FROM job_run;
```

**未关闭的告警待办**

```sql
SELECT id, kind, title, created_at FROM todo
WHERE state = 'OPEN' AND kind IN ('JOB_FAIL', 'SYNC_FAIL') ORDER BY created_at;
```

**关闭已处理的告警待办**（「定时任务出错」「同步失败」）

```sql
UPDATE todo SET state = 'DONE', done_at = NOW()
WHERE state = 'OPEN' AND kind IN ('JOB_FAIL', 'SYNC_FAIL');
```

**企微推送统计**（`FAIL` 表示 3 次都失败、已放弃）

```sql
SELECT push_state, COUNT(*) FROM todo WHERE push_state IS NOT NULL GROUP BY push_state;
```

**企微故障排除后，重新推送失败的消息**

```sql
UPDATE todo SET push_state = 'PENDING', push_tries = 0 WHERE push_state = 'FAIL' AND state = 'OPEN';
```

**各表占用空间**

```sql
SELECT table_name, ROUND((data_length + index_length) / 1024 / 1024, 1) AS mb
FROM information_schema.tables WHERE table_schema = DATABASE() ORDER BY mb DESC;
```

## 附录 B：调用管理接口

页面上能做的优先在页面上做。确实需要调接口时：

**第 1 步：获取令牌**（有效期 12 小时）

```bash
read -rp '账号：' U; read -rsp '密码：' P; echo
TOKEN=$(U="$U" P="$P" python3 -c 'import json,os,urllib.request as r;q=r.Request("http://127.0.0.1:8000/api/auth/login",json.dumps({"username":os.environ["U"],"password":os.environ["P"]}).encode(),{"Content-Type":"application/json"});print(json.load(r.urlopen(q))["token"])')
```

**第 2 步：调用接口**，例如查看金蝶同步状态：

```bash
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/api/erp/docs/sync/status
```

| 用途 | 方法与地址 |
|---|---|
| 手动巡检 | `POST /api/admin/jobs/tick` |
| 金蝶单据同步状态 | `GET /api/erp/docs/sync/status` |
| 金蝶单据增量 / 全量同步 | `POST /api/erp/docs/sync`、`POST /api/erp/docs/sync?full=true` |
| 金蝶物料同步 | `POST /api/master/sync/material` |
| 企微通讯录同步 | `POST /api/admin/wecom/sync-contacts` |
| 立即对账 | `POST /api/recon/run` |
